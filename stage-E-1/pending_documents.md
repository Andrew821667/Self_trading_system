# Что осталось добрать по документам

Список того, чего не хватает в собранном инвентаре
(`stage-E-1/inventory/events.jsonl`, **293 события** семейства E-1 за
2021–2025 из AZIPI) и что для этого нужно.

Собрано было 812; ревизия по текстам исключила 519 как не относящиеся к
семейству (обычный buyback по ст. 72 и отчёты постфактум) — они лежат в
`inventory/out_of_family.jsonl`, см. `coverage_report.md`, раздел
«Ревизия 2026-08-24».

Машинный срез в любой момент:

```sh
uv run python scripts/validate_e1_inventory.py   # тип x год x источник x pending
```

## 1. Всё до 30.07.2021 — источник нужен другой

Архив AZIPI начинается **30.07.2021** (проверено: самая ранняя собранная
дата события; за 2020 и I полугодие 2021 поиск отдаёт ноль). Отсутствуют
2019, 2020 и семь месяцев 2021 — примерно **2,6 года из 7**, требуемых ТЗ. Варианты: архив
Интерфакса (`e-disclosure.ru`, закрыт антиботом для этой среды),
`disclosure.ru`/`disclosure.1prime.ru` (доступны, поиск по типам не
исследован), либо выгрузка с машины владельца.

## 2. Условия предложений — по 21 событию их нет в самом сообщении

Из 196 предложений 175 идут полным нумерованным шаблоном (цена, гарант,
приобретатель читаются из текста), а 21 — короткое уведомление вида
«поступило обязательное предложение», где условия лежат в **приложенном
файле**. Для них цена/гарант/приобретатель принципиально недостижимы из
скачанного сообщения — нужен сам файл предложения (ссылка обычно ведёт на
`disclosure.ru/issuer/<ИНН>/` или на сайт эмитента).

Получить список этих 21:

```sh
uv run python - <<'PY'
import json, pathlib
rows = [json.loads(l) for l in open('stage-E-1/inventory/events.jsonl', encoding='utf-8')]
for r in rows:
    if r['event_type'] == 'voluntary_or_mandatory_offer' and 'procedure_price' in r['pending_fields']:
        print(r['announcement_date'], r['issuer'][:60], r['source_document_refs'][0])
PY
```

## 3. Ценовая база — почти всегда в приложении, не в сообщении

Из 121 найденного пункта о цене саму базу (биржевая средневзвешенная /
отчёт оценщика) называет **один**. Остальные дают только число. База — в
резолютивной части отчёта оценщика, который прикладывается отдельно.
Признак П-3 чек-листа («ценовая база чистая») без него не проверяется.

## 4. Разделение ст. 84.7 и 84.8 — только по тексту

Обе процедуры называются «требование о выкупе» и в таксономии агентства не
различаются, поэтому все 97 таких событий лежат в
`squeeze_out_request_95`, а `forced_buyback` пуст. Разделение — задача
экстракции по тексту, не индексации.

## 5. `buyback_art_75_76` — событий нет, нужен другой заход

Ревизия закрыла вопрос отрицательно: коды 4005185 / 1080045 к этому
семейству не относятся (подробности в `coverage_report.md`). Прямого типа
сообщения под ст. 75–76 в таксономии агентства нет — право требовать
выкупа возникает из решения общего собрания (реорганизация, крупная
сделка, делистинг), которое раскрывается в общей категории «Решения общих
собраний акционеров».

Возможный путь, не пройденный: взять косвенные триггеры `1079921`
(исключение бумаг из торгов — делистинг) и `1079194` (заявление в ЕГРЮЛ о
реорганизации), затем по каждому эмитенту искать уведомление о праве
требовать выкупа. Это отдельная работа.

## Чего делать НЕ нужно

Не пытаться закрыть pending-поля регулярками до конца. По ТЗ 6.3–6.5
структурная экстракция — предмет Stage E1: валидация схемы, закрепление
`extraction_model`/`prompt_version`, золотой регрессионный набор с ручной
проверкой эталонов. Ad-hoc парсинг в Фазе A положил бы незафиксированную,
непроверяемую экстракцию в основание всего исследования.
